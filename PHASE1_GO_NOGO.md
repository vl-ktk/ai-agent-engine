## 2. Подтверждённые факты

1. **Исходник и прототип.** Публичный MIT-репозиторий vl-ktk/ai-agent-engine; разрешённый набор локальных инструментов, изолированная временная рабочая папка, журнал без содержимого запросов, ограничение шагов. Наличие пилота не означает, что готова очередь, распределённая память или автономный сервер.
2. **Реальный ChatGPT OAuth.** Владелец завершил личный Sign in with ChatGPT и подтвердил ChatGPT plan usage GRANTED в существующем Codespace 2026-11-16. Его токены не поступали в публичный GitHub или в этот аудит.
3. **Реальные модельные вызовы.** Один краткий GPT smoke-test, затем одна объединённая проверка GPT + Claude 2026-11-17: по сохранённому отчёту владельца 12/12 PASS. GPT вызвал функции записи и чтения файла во временной песочнице; Claude Code 2.1.326 дал один текстовый ответ под claude.ai/pro. Это не длительный стресс-тест.
4. **Офлайн CI.** Последний PR #12: 125/125 локальных тестов; GitHub Actions run 44040107261 — 4/4 PASS: Linux Python 3.11, 3.12, 3.13 и Windows Python 3.12. Это проверки кода с искусственными OAuth-токенами, **не** живая проверка refresh.
5. **Refresh/revoke и перенос.** Автообновление перед GPT-запросами, межпроцессная блокировка refresh/logout, ручное отключение с попыткой remote revoke и защищённый staged import на будущую VM реализованы и проверены офлайн. Реальная ротация токена, remote revoke, повторный вход после истечения полномочий, VM/SSH-перенос и восстановление после падения **не проверены**.
6. **Пределы текущей среды.** GitHub Codespaces пригоден для существующего личного теста, но сам по себе не доказывает непрерывную работу 24/7, независимость от домашнего ПК на постоянном VPS, требуемые разрешения Claude или безопасность production-развёртывания.

## 3. Условия и ограничения провайдеров

### GPT / OpenAI

- Для подходящего open-source личного агента OpenAI документирует Sign in with ChatGPT и отдельный сценарий **self-hosted VM**, с независимым host ID и защищённым обращением с credentials. Это основание для инженерного пилота, но не доказательство соответствия будущего закрытого или обслуживающего клиентов SaaS.
- ChatGPT Plus имеет общие лимиты использования плана; они не становятся безлимитными при запуске собственного клиента. Запрещено трактовать подписку как универсальный бесплатный API-ключ; нельзя автоматически переключаться на платную маршрутизацию.
- Официальный refresh использует привязанный к регистрации client ID и обновляемый refresh token. Межпроцессная сериализация и защищённое хранилище обязательны. Успешные синтетические тесты не заменяют владельческий тест настоящей ротации.

### Claude / Anthropic

- Anthropic указывает, что официальный Claude Code и claude -p при входе через Claude-план сейчас расходуют лимиты подписки. Это **не** безусловное разрешение использовать OAuth в своём серверном продукте.
- OAuth Claude предназначен для обычного использования официальных приложений; для сторонних продуктов Anthropic рекомендует API-key/коммерческие способы. Нельзя переупаковывать подписку для пользователей или собирать чужие Claude-токены.
- CLI-проверка не удостоверяет, выключено ли оплачиваемое Extra Usage. При любом будущем разрешённом живом тесте сначала проверить настройку расходов, а не допускать неожиданных списаний.
- Не обходить ограничения через собственный OAuth-клиент, подмену идентичности, извлечение или копирование Claude credentials. Текущий пилот оставляет вход официальному немодифицированному Claude Code.

## 5. Что должно произойти до полного GO

1. **Авторизация:** при естественной потребности выполнить один ограниченный GPT-запрос с сохранённой действующей учётной записью и подтвердить безопасный реальный refresh, не публикуя токены. Не форсировать истечение, не делать многократных ручных входов с телефона. Реальный revoke проверять лишь при намеренном отключении владельцем, не сейчас.
2. **Claude:** получить применимое разъяснение политики/выбрать разрешённый режим для фонового исполнителя; провести только санкционированный тест лимитов и отказа без перехода на Extra Usage.
3. **Безопасность:** на будущем VPS определить владельца процесса, отдельный host ID, хранение и резервирование секретов, минимальные разрешения, сеть, журналирование, ограничение инструментов, восстановление после падения.
4. **Надёжность и лимиты:** проверить очередь, конкурентные изменения, остановку при квоте, восстановление после рестарта, остановку процесса при отказе модели, отмену задач и неизменность рабочего проекта при тестах.
5. **Стоимость:** перед созданием VPS получить актуальную цену и наличие, зафиксировать месячный потолок и отдельное согласие на расходы.
6. **Выкладка:** проверить исходную production-версию, провести тесты и получить отдельное разрешение на production/изменение чужих проектов или токенов. Само одобрение этого документа не считается разрешением на эти операции.

## 6. Ближайший разрешённый шаг

**Начать этап 2 — архитектуру AI Agent Engine, с подпункта 2.1: границы компонентов и интерфейсы**, затем 2.2–2.7 в утверждённом порядке. Можно проектировать и проверять офлайн без новой VM и без доступа к действующим токенам. Этап 1 формально остаётся открытым до владельческой приёмки и остаточных LIVE/политических подтверждений.
