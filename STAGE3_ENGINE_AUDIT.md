# AI Agent Engine — технический аудит 3.7

**Дата:** 2026-11-17 (Europe/Kyiv)  
**Объект:** только `vl-ktk/ai-agent-engine`, исходный `main` `f0483fc18813884b907859614c6400cfd606a8fb`.  
**Ограничение:** статический разбор текущего исходника и синтетические офлайн-тесты. Не было новых вызовов GPT/Claude, доступа к живым токенам, VM, production или чужим проектам.

## Итог GO/NO-GO

- **GO для дальнейшей офлайн-разработки и публикации экспериментального Python-прототипа**: базовая петля агента, роль/контекст задачи, явный выбор модели, проверяемые разрешения на инструменты, запись/чтение в ограниченной тестовой директории, безопасная обработка ошибок и прерывание между шагами функционируют в пределах синтетических тестов.
- **NO-GO для постоянно работающей автономной системы или серверного production-релиза**: нет реализованных устойчивой очереди, централизованной политики проектов, транзакционного выполнения инструментов, восстановления задач после падения, ОС-изоляции исполнителей, серверной авторизации и эксплуатационных метрик. Это отдельные этапы 4–10. Старые LIVE 12/12 доказывают только ограниченный личный сценарий, не пригодность к непрерывной работе.
- Формальное завершение **3.7** и разрешение на последующий релиз требуют отдельной **приёмки владельца** после публикации результатов CI. Завершение этого аудита само по себе не разрешает запуск VM, платные вызовы или production.

## Воспроизведённые дефекты и исправления 3.7

1. **F-01 / подтверждён:** до исправления `ModelTurn(final_text=123)` приводил к `AgentResult(status="done", answer=123)`, пустой финальный текст тоже считался успехом. Добавлена строгая проверка непустой строки и верхняя граница **1 048 576 символов**; ошибки моделей безопасно превращаются в `model_error`.
2. **F-02 / подтверждён:** до исправления движок принимал произвольно длинный prompt без проверки типа. Добавлен предварительный отказ для пустого, нестрокового или превышающего **65 536 символов** prompt до вызова модели.
3. **F-03 / подтверждён:** CI-сканер пропускал файл с NUL-байтом, потому что NUL допустим при UTF-8 декодировании. Добавлен запрет NUL и синтетический тест.
4. **F-04 / интеграционная регрессия:** новым отдельным тестом проверены запрет невыданного инструмента, невозможность чтения за пределами sandbox даже при внедрённой инструкции, разрешённая запись/чтение и аудит успешного сеанса.

## Известные ограничения, не являющиеся выполненными работами 3.7

- **Изоляция и права.** Нет независимого OS-процесса/контейнера на агента; Windows-защита файлов рассчитана только на доверенный локальный каталог. Текущие `project_id`/`agent_id` — контекст и аудит, **не** серверное право доступа.
- **Восстановление/надёжность.** История в памяти, нет устойчивого задания, подтверждения транзакций, дедупликации side effects или автоматического rollback инструмента. При падении процесса результат инструмента может сохраниться без фиксации успешного шага.
- **Провайдеры.** Нет подтверждённых лимитов непрерывного GPT OAuth на VM, реального refresh/revoke, правомерности постоянно работающего Claude Pro, общего бюджетного контроллера и ограничений стоимости. Отдельные решения по этапу 1 остаются в `PHASE1_GO_NOGO.md`.
- **Секреты/сборка.** Сканер обнаруживает только выбранные шаблоны; optional SIWC зависимости заданы диапазоном, а actions используют версии-теги, не SHA-хеши. Для production нужен отдельный supply-chain и секретный аудит.
- **Многопользовательность.** Provider factories доверенные и могут случайно вернуть один stateful-объект модели для нескольких задач; при будущей реализации требуется контролировать жизненный цикл адаптера и разделение хранилищ проектов.

## Контрольные команды

```bash
python -m unittest discover -s tests -q
python -m compileall -q ai_agent_engine tests scripts
python scripts/check_public_source.py
python -m ai_agent_engine
python -m pip wheel --no-build-isolation --no-deps --wheel-dir <temporary-directory> .
```

Все тесты выполняются с синтетическими данными и не требуют сети, секретов или API-средств. На момент аудита исходная база — **168/168**; после исправлений и интеграционных тестов — **171/171 PASS локально**. Проверка на матрице GitHub и итоговая ссылка добавляются в `HANDOFF.md` после PR.

**Граница приёмки:** владелец может принять **технический офлайн-движок этапа 3** как основу для следующей разработки. Нельзя принимать этим же решением всю будущую автономную AI-систему как готовую к промышленному запуску.
