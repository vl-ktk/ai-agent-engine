## 1. Подтверждение жизнеспособности схемы авторизации и затрат

### Контрольный список подпунктов

- [x] **1.1. Проверить актуальные официальные правила OpenAI SIWC/ChatGPT Plus для open-source и self-hosted VM.** **Завершена только документальная проверка (2026-11-16):** OpenAI прямо описывает OSS-приложения на self-hosted VM; OAuth выполняется локально, VM использует отдельный host ID; плановый доступ ограничен условиями и квотами. Через этот маршрут Responses требует `store: false`, `stream: true`, а некоторые hosted-инструменты недоступны. Это **не** проверка фактической авторизации и **не** заключение о соответствии ещё ненаписанного приложения.
- [x] **1.2. Подтвердить применимость правил именно к нашей архитектуре — документальный архитектурный аудит (2026-11-16).** **Условный PASS по опубликованным условиям OpenAI:** реальные рабочие исходники OSS-клиента/движка и оркестрации публикуются, а отдельный экземпляр запускается владельцем на личной self-hosted VM; данные, рабочие проекты, токены и конфигурации остаются приватными. Такой сценарий прямо описан OpenAI. Динамическая регистрация OSS-клиента предусмотрена через `dynamic_agent_client`, без партнёрского API-ключа/секрета; предварительное отдельное одобрение *не указано для этого OSS-пути*. **Граница:** если приложение фактически будет закрытым удалённым SaaS или сервисом для других клиентов, использовать эту оценку нельзя: OpenAI направляет paid/remotely hosted продукты в отдельный interest form. **Не доказано до создания кода:** что наш конкретный клиент соответствует условиям, OAuth разрешит нужные scopes, GPT-модель ответит и будут доступны нужные квоты. Живые проверки остаются подпунктами 1.4–1.7. Не обещать универсальное разрешение OpenAI.
- [x] **1.3. Проверить официальные варианты подключения Claude — документальная проверка (2026-11-16).** **Условный PASS для официального Claude Code, не для произвольного собственного OAuth-клиента.** Pro ($20/мес. при помесячной оплате) включает официальный Claude Code; при входе через подписку Anthropic сообщает, что `claude -p` и Claude Agent SDK пока расходуют лимит подписки (пауза прежних изменений от 2026-06-15 подтверждена 2026-10-07). Подписка ограничена общими 5-часовыми и недельными квотами. Приложение Claude Code можно запускать через SSH и проходить официальный интерактивный вход с ручным кодом. **Правовое ограничение:** сторонний сервис не должен сам предлагать вход Claude.ai, собирать/передавать OAuth-токены и перенаправлять обращения других пользователей через Pro; для сторонних продуктов Anthropic предписывает API-ключи либо отдельное согласование. **Предпочтительный кандидат:** неизменённый официальный Claude Code под личным логином владельца, вызываемый как CLI-исполнитель; без `ANTHROPIC_API_KEY`, чтобы не возникало API-списаний. **Не проверено:** что именно наша автоматическая оркестрация на VPS в этой форме будет разрешена/стабильна и что один реальный `claude -p` под Pro сработает. Живой тест добавлен в 1.6; не сохранять Claude OAuth-токены в нашем приложении.
- [x] **1.4. Создать минимальный рабочий open-source прототип агента** для проверки входа и одного безопасного задания. До начала правок определить его официальный источник, лицензию, структуру и защиту секретов. **Реализовано, проверено и принято владельцем 2026-11-16:** публичный MIT-репозиторий [vl-ktk/ai-agent-engine](https://github.com/vl-ktk/ai-agent-engine), `main`, HEAD `c0b393610bbe48e2fc98b231a2f7f5229b69777e`; минимальный Python runtime с модельно-независимым интерфейсом, ограниченным циклом инструментов, allowlist, безопасной тестовой папкой, блокировкой перезаписи и журналом без содержимого запросов. `python -m ai_agent_engine` — PASS, 3 шага; `python -m unittest discover -s tests -v` — 10/10 PASS. Файлы `README`, `LICENSE`, `.gitignore`, 4 исходника и тестовый модуль сверены с GitHub посимвольно; `HANDOFF.md` в репозитории проверен отдельно. Никакого реального GPT/Claude, OAuth, платного API или VPS пока нет. Подпункт 1.4 закрыт; реализация 1.5 ведётся отдельно.

Пройти реальную OAuth-авторизацию пользователя без зависимости от домашнего ПК** через Sign in with ChatGPT (PKCE, consent, нужные scopes, собственный host ID); не передавать токены в чат или Git. **Прогресс 2026-11-16:** добавлены `ai_agent_engine/siwc.py`, CLI `ai_agent_engine/auth.py` и `requirements-siwc.txt`; реализованы локальные `127.0.0.1` callback, `state`/`nonce`/PKCE, выдача и повторное использование `client_id`, проверка подписанного OpenAI ID-токена через JWKS, проверка выданных scopes и сохранение секретов вне Git. ## Общие условия для всех этапов

1. **Не выдавать задуманные функции за уже существующие:** подтверждать реальные тесты, версии и результаты.
2. **Без согласования не делать:** покупки/платные API, production, изменение секретов/прав, опасные удаления, сообщения внешним людям и самовольную передачу чужой текущей задачи.

4. **Избегать лишних структур:** новые оркестраторы и специализации вводятся только когда дают измеримую пользу.
5. **Текущая работа:** продолжать **этап 1** по уже отмеченным подпунктам и результатам, без повторного выполнения проверенных действий. Для будущих этапов сначала уточнять технические детали и критерии приёмки с владельцем.
