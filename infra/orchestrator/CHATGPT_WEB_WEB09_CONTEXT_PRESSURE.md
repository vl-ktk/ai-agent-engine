# WEB-09 — контроль заполнения контекста (только offline/mock)

**21.11.2026.** Исходный пакет `0.3.34a0`; девятый из 20 пунктов внутреннего плана 7.11. Реализация: `ai_agent_engine/chatgpt_web_context.py` и opt-in интеграция в `WebAgentModelRegistry` / `WebAgentSessionRegistry`; unit: `tests/test_chatgpt_web_web09.py`.

## Контракт

- `TrustedAgentContextPolicy`: фиксирует owner/project/agent/ChatGPT Project, условный бюджет, строгие настраиваемые пороги (по умолчанию **60/75/90%**) и резерв ответа. Не допускает повторной регистрации и чужого проекта.
- `ProjectChatManager.active` указывает на конкретную активную *mock* conversation. `ScopedContextUsageSource.read_current` получает её ID вместе с профилем; `ContextUsageEvidence` должен подтвердить каждый scope-field, актуальность и результат верификации. Проверка находится **в той же агентной FIFO**, после membership/model/effort/instructions, до `BrowserPort.complete`.
- `exact`: единственное совпадающее точное измерение; `bounded`: нижняя оценка и **подтверждённая верхняя граница**; `unknown`: измерений нет. Монитор всегда использует верхнюю границу, прибавляет UTF-8 длину полного системного сообщения и нового запроса, 32 единицы накладных расходов и резерв ответа. Эти величины являются **консервативной proxy-эвристикой, не настоящим точным счётчиком токенов ChatGPT**. Новая политика/измерительный источник должны быть отдельно проверены перед live применением.
- Проектируемая верхняя загрузка **меньше 60%** → `OK`, **от 60%** → `WARN` (результат доступен в `last_decision`, запрос разрешён), **от 75%** → `ROTATE` (запрос блокируется с требованием безопасной ротации), **от 90%** → `EMERGENCY` (запрос блокируется). Пороговые сравнения целочисленные, включая точные границы.
- `unknown` → `HOLD` и запрет отправки; ложное подтверждение, неверный scope, непоследовательные числа, отрицательные/bool/non-int, stale evidence, ошибка источника, регресс измеренного нижнего bound в рамках того же conversation → отказ. После явной ротации mock-чата допускается новый отсчёт с нуля. Текст запроса/секреты в ошибках не раскрываются.
- Нет точного токен-счётчика веб-интерфейса и способа доказать правильность правдоподобного, но лживого `verified=True` mock proof. Монитор способен **отклонить противоречивые/неограниченные значения**, а не детектировать любую сфабрикованную оценку.
- WEB-09 **не** создаёт новый чат, не повторяет запрос, не переносит контекст, не записывает checkpoint. Это **WEB-10/11**; пока сигналы ROTATE/EMERGENCY/HOLD останавливают запрос. Данные in-memory, не persistent state. Защищён только opt-in путь `WebAgentModelRegistry.run` с подключённым monitor; legacy direct sessions и реальные браузеры этим не покрыты.

## Проверки

Новые тесты проверяют обе стороны каждого порога, иной 50/65/80 policy, response reserve, bounded estimate (по верхнему пределу), отсутствие/ложность/откат измерений, wrong project/profile/conversation, stale/unverified/ошибку источника, независимых агентов, смену чата, отсутствие автоматической ротации, последовательность membership→model→usage→browser и FIFO при одновременной ручной mock-ротации. Реального ChatGPT UI, Netcup, сторонних средств и оплачиваемого API не вызывали.

**Локальная проверка:** 15/15 новых WEB-09 unit, полный regression **1211 OK (3 skipped)**, `compileall`, `git diff --check`, wheel `ai_agent_engine-0.3.34a0-py3-none-any.whl` PASS. **GitHub CI:** результаты фиксируются отдельно после публикации source; отсутствие живого токен-счётчика и разрешения на ChatGPT Web остаётся `POLICY_HOLD` до WEB-17.
