# 5.1–5.3 — API приёма задач (локальный прототип)

**Статус:** проверяемая локальная реализация подпунктов 5.1–5.3 AI Agent Engine.
Никаких моделей, платных API или новых VPS не требуется. Сервер Netcup здесь
не перенастраивается.

## HTTP-контракт

- `POST /v1/tasks`, `Content-Type: application/json` (допустим UTF-8 charset).
- Тело: **три обязательных строковых поля**:
  - `project_id` — идентификатор проекта 1–128 символов:
    латинские буквы, цифры, `_`, `.`, `:`, `-`; первый символ — буква/цифра.
  - `title` — непустое название длиной до 1024 символов, без управляющих.
  - `prompt` — непустая постановка задачи до 32768 символов.
- Опционально `parent_task_id`: ранее выданный `task_<32 hex>` или
  `subtask_<32 hex>` из **того же проекта и того же владельца**.
  Это означает подзадачу; отсутствие поля означает корневую задачу.
- Кодировка строго UTF-8; JSON-ключи не должны повторяться. Лишние поля и
  вложенные объекты вместо строк отклоняются. Размер запроса не более 49152
  байт. HTTP `Content-Length` обязателен.
- Успех: **`202`**, JSON с `status=accepted_in_memory`, `receipt`,
  `task_id`, `owner_id`, `project_id`, `parent_task_id`, `kind`.
  `receipt` — только локальный порядковый номер приёма, не стабильный ID.
  `task_id` — UUID4 с префиксом `task_` или `subtask_`, сохраняется
  у принятой записи при жизни процесса. Не гарантия обработки/сохранности.
  Тело задачи обратно клиенту не отправляется.
- `GET /v1/tasks/{task_id}`: **`200`** и только безопасные поля идентичности
  и список ID зависимостей `depends_on` для записи в разрешённых владельцу
  проектах; **`404`** для чужого, некорректного и неизвестного ID.
- `PUT /v1/tasks/{task_id}/dependencies` и
  `GET /v1/projects/{project_id}/task-order` — DAG-зависимости,
  проверка циклов и порядок задач ([пункт 5.3](./TASK_DEPENDENCIES.md)).

| HTTP-код | Причина |
| --- | --- |
| 400 | Некорректный JSON/UTF-8, нулевая длина, ошибочный Content-Length или неполное тело |
| 404 | Неизвестный путь |
| 403 | Проект вне разрешённой сервером области |
| 404 | Родительская задача чужая/неизвестная или чтение чужой/неизвестной записи |
| 405 | Неподдерживаемый метод |
| 411 | Отсутствует Content-Length |
| 413 | Тело больше установленного лимита |
| 415 | Content-Type не JSON |
| 422 | Недостающие, неизвестные или неправильные поля |
| 503 | Приёмник заполнен (по умолчанию максимум 128 задач) |
| 409 | Попытка создать циклическую зависимость (5.3) |

Ошибки возвращают только безопасный машинный код, не цитируют запрос,
промпт, секреты, URL или содержимое исключений. HTTP-запросы и их данные
не записываются в журнал.

## Локальный запуск (не на публичном VPS)

В явном порядке из checkout, без внешних библиотек:

```bash
python3 -m ai_agent_engine.task_api --port 8765 --owner-id owner-a --project-id project-a
```

Слушатель жёстко ограничен `127.0.0.1`, доступ извне не открыт.
В отдельном терминале:

```bash
curl -i --request POST http://127.0.0.1:8765/v1/tasks \
  --header 'Content-Type: application/json' \
  --data '{"project_id":"project-a","title":"Пробная задача","prompt":"Подготовить план"}'
```

Реальная проверка HTTP производится автономными тестами без ручного запуска
службы:

```bash
python3 -m unittest tests.test_task_api -v
python3 -m unittest discover -s tests -q
```

## Принципиальные границы

1. Реализация `TaskInbox` держит ограниченное число объектов **только в RAM**.
   При завершении процесса данные исчезнут: **долговечная очередь — 5.5**.
2. Привязка к `OwnerScope` задаётся **только доверенной конфигурацией
   запуска сервера**. HTTP-клиент не может переопределить `owner_id` или
   разрешённые проекты. Чужие записи не выдаются и не становятся родителями
   подзадач. Это **не аутентификация клиентов**: любой, кто получил доступ
   к этому локальному сокету/порту, сможет действовать от имени владельца,
   назначенного серверу. Не выставлять в сеть и production до полноценной
   аутентификации/авторизации.
3. Идентификаторы `task/subtask/owner` — **5.2**; DAG зависимостей — **5.3**;
   приоритеты — **5.4**, назначение и выполнение — последующие
   пункты. Получение `202` не означает, что модель начала работу.
4. Никакой работающей версии Netcup или рабочей SQLite эта реализация не
   изменяет. В 5.1–5.2 выполнены локальные unit/HTTP-тесты, код публикуется
   в утверждённый GitHub `main` без server-side деплоя.
