# Stage 7.7 — one-project host readiness (read-only, no deploy)

**Purpose:** audit an already provisioned local Linux runtime for the **only**
approved scope `vl-ktk / ai-agent-engine`, before preparing a separate
owner-controlled release. This script cannot authorize a deployment. It is
source-only and has **not** been executed on Netcup.

`python -m ai_agent_engine.diagnostic_host_preflight --config /path/to/private/runtime.json`
is a future **operator/owner-workflow** hook, not a user-required Windows
command. It returns code `0` for an internally consistent *candidate* and
code `2` for `HOLD`. JSON output has only safe check names, blocker names
and the local Git SHA — no private paths, prompts or credentials.

## What is actually checked

1. The existing owner-provisioned JSON is a regular `0600` file inside a
   private `0700` directory, exact schema 1, exactly one owner/project and
   one Git source. The example JSON in this repository is **not** proof of
   actual paths, approvals or installed runtime on Netcup.
2. The project registry, project DB, workspace/source and socket runtime
   directory are already present, private and not symlinks. No directories
   are created, no modes or permissions are changed.
3. Read-only, inode-pinned SQLite inspection checks the known private DB
   application IDs and schema versions (`TaskInbox v14`, approved project
   registry v1, project workspace v2), and verifies a matching **active**
   approval row/project identity. This confirms internal consistency of
   existing records; it is **not** external authentication of an owner button.
4. Active SQLite writer locks or pending WAL/SHM/journal files cause HOLD.
   No new `.sqlite3`, sidecar, migration, WAL, owner approval or task row is
   ever generated by the checker. Foreign-scope task rows, unfinished
   `ASSIGNED/RUNNING` state or unresolved delivery rows also cause HOLD.
5. The trusted project Git checkout must have a verifiable stable `HEAD`,
   no uncommitted tracked/untracked changes, and source path exactly under
   the configured private workspace root. A mismatch produces HOLD.

The check is deliberately conservative. An already running TaskInbox or
registry **will be blocked**, because preflight must never compete with the
single active writer or read an inconsistent mutable live state.
