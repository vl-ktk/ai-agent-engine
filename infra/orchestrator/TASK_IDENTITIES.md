# 5.2 — идентификаторы и изоляция задач AI Agent Engine

**Область:** локальный прототип из `ai_agent_engine/task_api.py`.
Только задачи оркестратора AI Agent Engine; без моделей, платных вызовов,
дополнительных серверов и изменений действующей установки Netcup.

## Схема идентичности

| Поле | Кто задаёт | Гарантия локального прототипа |
| --- | --- | --- |
| `owner_id` | Доверенный администратор при запуске сервера (`--owner-id`) | Нельзя подменить JSON-запросом; один процесс/handler обслуживает явно назначенного владельца |
| `project_id` | Клиент при отправке, проверяется по `OwnerScope.project_ids` | Чужой проект отклоняется `403` |
| `task_id` | Сервер генерирует `task_` + UUID4 (32 lowercase hex) | Уникальный неизменяемый ID корневой задачи внутри временного inbox |
| `subtask_id` | Сервер генерирует `subtask_` + UUID4 в поле `task_id` | Уникальный неизменяемый ID подзадачи |
| `parent_task_id` | Клиент передаёт существующий ID родителя | Родитель обязан принадлежать **тому же владельцу и проекту**, иначе `404` |
| `receipt` | Сервер, возрастающий счётчик | Только временная квитанция приёма, не ID задачи |

Запрос не принимает `owner_id` или произвольный `task_id`: идентификатор
задачи назначает сервер. `TaskRecord` неизменяем, а индекс ID создаётся
под одним lock одновременно с добавлением записи. ID остаётся тем же при
повторном чтении и для связи родитель → подзадача; UUID4 не является
последовательным счётчиком. Подзадачи могут иметь свои подзадачи.

## Проверка доступа

- Любое создание требует доверенного `OwnerScope`; сервер без него не стартует.
- Создание в неразрешённом проекте → `403 project_forbidden`.
- Чужой или отсутствующий родитель → одинаковый `404 parent_not_found`.
- `GET /v1/tasks/{task_id}` возвращает `200 found` с идентификаторами
  и типом **только** для разрешённой записи. Для неизвестного и чужого ID
  одинаковый `404 not_found`. `title`/`prompt` в ответе отсутствуют.
- Внутренние `snapshot(scope)` и `get(id,scope)` тоже фильтруют по
  владельцу **и** проекту, в том числе когда два владельца делят один inbox.
- JSON с `owner_id`, `task_id` или посторонними полями → `422 invalid_task`.

## Безопасная локальная проба

```bash
python3 -m ai_agent_engine.task_api --port 8765 --owner-id owner-a --project-id project-a

curl -sS --request POST http://127.0.0.1:8765/v1/tasks \
  --header 'Content-Type: application/json' \
  --data '{"project_id":"project-a","title":"Задача","prompt":"Создать отчёт"}'
```

Из ответа скопируйте `task_id`, затем создайте подзадачу:

```bash
curl -sS --request POST http://127.0.0.1:8765/v1/tasks \
  --header 'Content-Type: application/json' \
  --data '{"project_id":"project-a","title":"Шаг 1","prompt":"Подготовить файл","parent_task_id":"task_ПОДСТАВЬТЕ_РЕАЛЬНЫЕ_32_HEX"}'
```

Второй запрос примет только действительный ID. Проверить метаданные можно
через `GET /v1/tasks/{task_id}`; текст постановки не возвращается.

## Что **не** реализовано

Это разграничение **серверных контекстов**, а не безопасная многопользовательская
служба: аутентификация удалённого/локального HTTP-клиента отсутствует.
Тот, кто может подключиться к локальному порту, действует в рамках
**назначенного серверу** владельца. Секреты, ACL и сетевые права здесь
не изменяются; публичное развёртывание запрещено до отдельной защиты.

Записи и индексы существуют только в памяти: после перезапуска ID не
сможет разрешиться, хотя его формат и значение, однажды выданные клиенту,
не меняются. Долговечность и восстановление ID относятся к **5.5**.
Граф зависимостей — **5.3**, приоритеты — **5.4**. Приём не запускает модели.

**Приёмка:** `python3 -m unittest tests.test_task_api -v`, полный regression,
проверка исходников/статического анализа и GitHub `main`. Локальные HTTP
тесты проверяют независимые owner scopes, общий inbox, чужие ID, запрет
чужих родителей, UUID и одновременное создание. Netcup не модифицируется.
