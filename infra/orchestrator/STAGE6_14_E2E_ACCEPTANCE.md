**Статус 18.11.2026: PARTIAL / LIVE BLOCKED.** Исходники и офлайн-сценарий подготовлены, но **обязательные реальные вызовы GPT и Claude через личные авторизованные подключения ещё не выполнены**. Не менять статус 6.14 на [x] из-за офлайн PASS.

## Цель и точный критерий

В ОТДЕЛЬНОМ одноразовом тестовом проекте пройти путь:

1. `TaskInbox.accept` принимает задачу в очередь под доверенным `OwnerScope`.
2. `GPTTaskExecutor` и `ClaudeTaskExecutor` выполняют ровно по одной назначенной задаче с отдельными `ActionGrant(EXTERNAL_REQUEST)`, контролируемой группой процессов и журналом permission/provider.
3. Проверить `SUCCEEDED`, точный тестовый маркер `AE-614-GPT` / `AE-614-CLAUDE`, `delivery.completed`, **ровно одно** успешное provider audit event.
4. `TaskArtifactTransfer` принимает достоверный текст ответа и **контроллером подготовленный**, а не сгенерированный моделью, файл `fixture.txt`, проверяет SHA-256 и сохраняет вместе в отдельную приватную task SQLite v10.
5. `TaskSourceVersionRecorder` сверяет заранее зафиксированный baseline Git SHA и итоговую чистую версию исходников. Далее доверенный тестовый контроллер создаёт **свой временный пробный коммит**, проверяет, что повторная сверка сообщает об изменении версии, и возвращается на baseline через `git switch --detach` **внутри TemporaryDirectory**, без изменения чужих репозиториев.
6. Закрыть процесс и SQLite, открыть SQLite повторно, проверить статусы, audit, исходный отчет/байты, SHA, процессный ledger `stopped`, Git source version.

Один реальный вызов каждой модели должен пройти **эту же** цепочку. Только после фактического live PASS и проверяемого протокола можно считать приёмку выполненной. Код не запускает долгоживущий daemon, не открывает API для внешних клиентов, не трогает Netcup и не изменяет основной GitHub `main` из acceptance.

## Инструмент

`ai_agent_engine/task_stage6_14_acceptance.py`:

```bash
# Детерминированная локальная проверка: реальные Linux subprocess, БЕЗ моделей:
python3 -m ai_agent_engine.task_stage6_14_acceptance --provider both

# ТОЛЬКО в личном уже авторизованном Linux Codespace,
# с явным поручением владельца на два личных модельных запроса:
python3 -m ai_agent_engine.task_stage6_14_acceptance --live --owner-approved --provider both
```

`--live` **не запускается без** `--owner-approved`; режим по умолчанию всегда офлайн. Реальный GPT идёт только через существующий SIWC/ChatGPT-plan `gpt_task_worker`, Claude через официальный `claude -p` и проверенный `claude auth status`. В Claude запрещены tools, MCP и API-key fallback, `ANTHROPIC_API_KEY` не наследуется. Никакого нового платного API не создаётся. Это не доказательство отсутствия расходования подписочных лимитов/Extra Usage; финансовый учёт этим сценарием не проверяется.

Перед живой проверкой владелец должен иметь **на одном Linux окружении** действующие личные GPT SIWC и Claude Pro авторизации. Нельзя копировать OAuth-токены в Git/чат и нельзя вносить изменения на Netcup ради теста.

## Границы безопасности

- Только тестовая `TemporaryDirectory`, новая private SQLite `0600`, закрытые workspace `0700`, отдельные Git репозитории без `origin`.
- Контроллерские Git-команды без shell-интерполяции/сетевых операций, с отключёнными глобальными настройками и hooks; probe-коммит и возврат только в пустой тестовой копии. **Нет** `git reset --hard`, `git push`, production deployment и модификации рабочего проекта.
- Модели видят короткий тестовый prompt с маркером; никакие исходники, секреты или платные ключи не отправляются им. Отчёты в SQLite живого сценария удаляются вместе с временной областью после проверки; в stdout выводится только статус и имена провайдеров без ответа модели.
- При неуспехе живого вызова нет fallback и автоматического повтора. Наличие когда-то успешных 6.2/6.3 не заменяет текущий 6.14 live E2E.
