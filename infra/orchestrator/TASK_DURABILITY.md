# 5.5 — долговечная очередь задач AI Agent Engine

**Результат:** `SQLiteTaskStore` сохраняет принятые задачи и подзадачи,
их серверные ID/владельцев/проекты, родителей, исходные тексты, текущие
приоритеты и граф зависимостей. После перезапуска процесса объекты и
связи восстанавливаются **с прежними ID и квитанциями `receipt`**;
следующий `receipt` продолжает счётчик, а не сбрасывается.

Никакой новый VPS, платный сервис, внешняя модель или резервный сервер
не требуется. Используется **один отдельный приватный файл SQLite**;
это хранилище очереди, **не копия** существующей рабочей БД контроллера
`engine.sqlite3`. Существующую БД Netcup и её backup jobs не меняли.

## Как включить на отдельной локальной тестовой среде

Создайте собственный каталог с правами `0700` **вне Git-репозитория** и
укажите путь к файлу очереди. Каталог уже должен существовать и
принадлежать тому же пользователю, от которого запускается процесс.

```bash
python3 -m ai_agent_engine.task_api \
  --port 8765 \
  --owner-id owner-a \
  --project-id project-a \
  --db /ПУТЬ_К_ПРИВАТНОМУ_КАТАЛОГУ/inbox.sqlite3
```

Файл создаётся с правами `0600`; процесс **отказывается** работать с
общедоступным родительским каталогом, открытым для других файлом,
симлинком, чужой/неузнанной БД или когда тот же файл уже используется
другим писателем. Администратор отвечает за путь и разрешения.
Без `--db` для обратной совместимости остаётся старый временный RAM-inbox.

В постоянном режиме:

- `POST /v1/tasks` → `202 accepted_durable` **после commit** записи;
  без `--db` → `202 accepted_in_memory`.
- Изменение приоритета/зависимостей `PUT` → `200` **после commit**;
  при отказе SQLite → `503 storage_unavailable` без содержимого промпта.
- Неверная зависимость/цикл/права отклоняются **до** попытки записи;
  неудачная SQL-транзакция откатывает все свои изменения.
- После повторного запуска `GET /v1/tasks/{id}`, `GET /task-order` и
  `GET /next-task` работают с восстановленными задачами и свойствами.
- Записи остаются ограничены максимальной вместимостью inbox — по
  умолчанию **128 задач**, в том числе восстановленных. Автоматической
  архивации/удаления завершённых задач пока нет (машина состояний — 5.7).

## Реальные механизмы сохранности

- SQLite с транзакциями, `foreign_keys=ON`, `synchronous=FULL` и
  rollback-журналом SQLite (временный служебный файл может появляться
  **во время транзакции**). Отдельных постоянных копий не создаётся.
- При запуске проверяются идентификатор приложения и версия схемы
  (с 5.6 схема v2 с `task_claims`, миграция v1 → v2 без переписи задач);
  чужая база не мигрируется. `integrity_check` и `foreign_key_check`
  должны пройти; при повреждённых правах/графе/циклах загрузка
  прекращается, **базу автоматически не перезаписывают и не удаляют**.
- Один процесс-владелец БД: неблокирующий `flock` предотвращает запуск
  второго писателя со старым RAM-кэшем.
- Все проверки области владельца/проекта и DAG выполняются под
  внутренним lock; SQL commit предшествует обновлению RAM и HTTP `202/200`.

**Проверено настоящим процессом:** локальный Python HTTP-сервер был
запущен с `--db`; были приняты задача и подзадача, изменены приоритет
и DAG; процесс остановлен через SIGTERM и запущен заново. Старые ID,
родитель, граф, приоритет, порядок выбора и продолжение `receipt`
подтвердились через реальные HTTP-запросы. Дополнительно проверены
отказы SQL, rollback и ограничения файловых прав.

## Чего это **не** обеспечивает

1. Это **устойчивость к перезапуску процесса**, не гарантия восстановления
   после уничтожения диска/VPS. Независимой off-host копии новой БД нет;
   существующие backup jobs Netcup не утверждаются как покрывающие её.
2. SQLite хранит тексты задач **в открытом виде на диске**; контроль доступа
   через `0600`/`0700`, **не шифрование**. Не передавать секреты в промптах.
3. Клиентской аутентификации HTTP ещё нет — только trusted `OwnerScope`
   и локальное прослушивание `127.0.0.1`. На публичный Netcup API
   **не выкладывали и порт не открывали**.
4. Нет состояний выполнения и resume исполнения модели. После рестарта
   восстанавливается **очередь и её порядок**, а не запущенный процесс
   исполнителя. Блокировка назначения — 5.6, машина состояний — 5.7,
   возобновление исполнения/повторы — 5.12.

Код: `ai_agent_engine/task_storage.py`, опциональный backend в
`TaskInbox`, параметр `--db` в `task_api.py`. Приёмка:
`python3 -m unittest tests.test_task_storage -v` и весь regression.
