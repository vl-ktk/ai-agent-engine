# AI Agent Engine — пункт 6.3: Claude Code Pro как исполнитель очереди

**Решение 18.11.2026: HOLD для интегрированного Claude Pro runner.**
Пункт 6.3 предусматривает альтернативу: либо живое подключение в
**подтверждённом разрешённом** режиме, либо документально обоснованный
HOLD/NO-GO. Здесь выполнена **вторая** ветка критерия, а не подключение
Claude к `TaskInbox`. Не выдавать этот статус за «два исполнителя работают».

## Уже доказано в проекте

- 17.11.2026 в существующем личном GitHub Codespace прошёл **один**
  реальный тест официального `claude -p` под собственной Claude Pro
  авторизацией владельца; общий старый пилот GPT+Claude — 12/12 PASS
  по сохранённому отчёту. `ai_agent_engine/acceptance.py` содержит
  ограниченный ручной диагностический запуск, но **не** адаптер
  `TaskInbox → TaskDeliveryManager → TaskProcessController → Claude`.
- 18.11.2026 GPT отдельно прошёл новую цепочку очереди (6.2). Это не
  переносит Claude автоматически в ту же авторизацию или режим.
- Существующий Netcup VPS в пункте 6.3 **не изменялся**. Нет живого
  подтверждения Claude task runner на Netcup, условий Extra Usage или
  разрешения на непрерывные фоновые задания Claude Pro.

## Официальные основания, проверенные 18.11.2026

1. [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference):
   официальный немодифицированный `claude -p` делает разовый SDK-запрос
   и выходит; `claude auth status` различает `claude.ai` и API key.
2. [Anthropic — Agent SDK с подпиской](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan):
   по актуальной заметке `claude -p`, Agent SDK и сторонние приложения
   **пока списывают лимиты подписки** при подписочном входе. Это правило
   **учёта**, не юридическое разрешение для всех продуктов и сервисов.
3. [Claude Code Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance):
   подписочный OAuth предназначен для обычного индивидуального
   использования официального Claude Code; при разработке продукта или
   сервиса Anthropic направляет к API-key/cloud provider маршруту,
   запрещает свой Claude.ai login, сбор и посредничество чужих токенов;
   размещение Claude Code внутри продуктов/hosted agent infrastructure
   имеет отдельные условия Commercial Terms. Там же отдельно сохранена
   возможность **самому конечному пользователю** войти в немодифицированный
   официальный бинарник со своей подпиской.
4. [Anthropic — Pro/Max/Ultra plan в Claude Code](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-max-or-ultra-plan):
   `ANTHROPIC_API_KEY` переводит CLI на платный API-маршрут. Возможность
   Extra Usage и настройки списаний не подтверждаются одной командой
   `claude auth status`.

Это техническая осторожная интерпретация правил для **нашего конкретного**
open-source личного AI Agent Engine, не юридическое заключение и не заявление,
что Anthropic полностью запрещает любые личные скрипты с `claude -p`.

## Отдельные режимы

| Сценарий | Решение 6.3 |
| --- | --- |
| Владелец вручную использует официальный Claude Code/`claude -p` со своей Pro в терминале | **GO для ранее проверенного личного пилота**. Не новый тест 6.3. |
| AI Agent Engine автоматически выдаёт Claude Pro задания из собственной SQLite-очереди | **HOLD**: нет однозначного подтверждения, что этот тип сторонней интеграции под подписочным OAuth укладывается в ordinary individual use. |
| Фоновый unattended Claude Pro worker 24/7 на существующем Netcup | **HOLD / запуск не разрешён** до уточнения режима у Anthropic; собственный сервер не снимает ограничение. |
| Публичный или многопользовательский движок расходует одну Pro-подписку за других, проксирует их OAuth | **NO-GO** для такой подписочной маршрутизации. |
| Anthropic Console API key, платные API кредиты, Extra Usage | **NO-GO по текущему решению владельца**; технически возможная отдельная ветка только после прямого согласования условий и расходов. |

## Что нужно для изменения HOLD

- Письменное/официальное уточнение допустимости **личного одноаккаунтного**
  self-hosted AI Agent Engine: доверенная очередь, CLI `claude -p` как
  одноразовый task worker, возможный unattended режим, без чужих
  аккаунтов, логина-посредника и токен-прокси. Пока такого подтверждения
  нет; **сам факт списания из Pro не заменяет его**.
- Либо отдельное решение Владислава о переходе на Anthropic API,
  применимых коммерческих условиях, бюджете и надёжных лимитах.
  Автоматически этого решения не принимать.
- Только после разрешённого режима: отдельный scoped Claude worker с
  `TaskPermissionGate`, единственной выдачей, строгим time limit,
  отключением неразрешённых инструментов, безопасной классификацией
  quota/auth/error, отказом от повторных side effects, без передачи
  подписочных секретов в AI Agent Engine; отдельный live task→Claude тест.

**Итог 6.3:** решение HOLD/NO-GO официально проверено и записано; именно
это является завершением **альтернативного** критерия пункта. Claude
**не подключён к очереди**, новые CLI/model вызовы не выполнялись,
Codespace не запускался, секреты/права/Netcup/чужие проекты не менялись,
новые расходы или подписки не создавались. Дальше **6.4** — общий
контракт задач/ролей/прав, без автоматического снятия Claude HOLD.
