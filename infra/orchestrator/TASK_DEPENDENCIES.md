# 5.3 — DAG зависимостей задач AI Agent Engine

**Область:** только локальный программный прототип системного оркестратора.
Задачи/подзадачи и их владельцы определяются 5.1–5.2; ни Netcup, ни
рабочую SQLite, ни другие проекты этот пункт не изменяет.

## Семантика

- Каждая новая задача из `POST /v1/tasks` начинает с **пустого** списка
  `depends_on`.
- Зависимость `A depends_on [B]` означает **B должна предшествовать A**.
  Это направленная связь предпосылки, а не иерархия `parent_task_id`.
  Родитель подзадачи **не становится автоматической зависимостью**.
- В каждый момент зависимости образуют DAG — направленный граф **без циклов**.
  Самоссылки, прямые и транзитивные циклы отклоняются до записи.
- Только ID задачи того же доверенного `owner_id` и того же `project_id`
  может стать предпосылкой. Для чужих/несуществующих ID — общий `404`.
- Максимум **64 различных** предпосылки у одной задачи. Обновление заменяет
  весь список атомарно, под lock, без частичных изменений при отказе.
- **Детерминированный топологический порядок:** каждая предпосылка идёт
  раньше зависимой задачи; среди одновременно доступных элементов
  используется порядок их приёма (`receipt`). Это **не приоритеты** и не
  запуск модели: отдельные пункты 5.4 и далее.

## HTTP для локальных проверок

Сервер запускается только на `127.0.0.1` с обязательным trusted owner scope:

```bash
python3 -m ai_agent_engine.task_api --port 8765 --owner-id owner-a --project-id project-a
```

Сначала принять обычные задачи через `POST /v1/tasks` по контракту
[`TASK_INTAKE.md`](./TASK_INTAKE.md), сохранить два выданных ID.

**Задать зависимости (полная замена):**

```http
PUT /v1/tasks/{task_id}/dependencies
Content-Type: application/json

{"depends_on":["task_0123456789abcdef0123456789abcdef"]}
```

Здесь оба ID должны быть **действительными, уже принятыми** ID в текущем
inbox. Для очистки списка: `{"depends_on":[]}`.

**Получить порядок задач проекта:**

```http
GET /v1/projects/project-a/task-order
```

Успех: `200 {"status":"ordered","project_id":"project-a","task_ids":[...]}`.
Для пустого разрешённого проекта возвращается пустой список. В ответе
нет названий, промптов или данных соседних проектов.

`GET /v1/tasks/{task_id}` теперь содержит также `depends_on`.

| Операция | Код | Значение |
| --- | --- | --- |
| `PUT /dependencies` | 200 | `dependencies_updated`, список предпосылок заменён |
| `PUT /dependencies` | 400 | Ошибка JSON, повторный ключ или неверная длина |
| `PUT /dependencies` | 404 | Целевая задача чужая/неизвестная (`not_found`) |
| `PUT /dependencies` | 404 | Предпосылка чужая/неизвестная (`dependency_not_found`) |
| `PUT /dependencies` | 409 | Прямой/транзитивный цикл (`dependency_cycle`), без записи |
| `PUT /dependencies` | 422 | Неверный массив ID, дубликат, превышено 64, лишние поля |
| `GET /task-order` | 200 | ID задач в допустимом топологическом порядке |
| `GET /task-order` | 403 | Проект за пределами `OwnerScope` |

Для `PUT` действуют те же ограничения `Content-Type`, `Content-Length`
и размера тела, что для `POST` (5.1). Ответы не отражают пользовательский
промпт и не раскрывают чужие задачи.

## Достоверная граница результата

Реализованы `TaskDAG` в `ai_agent_engine/task_dag.py`, совместное
обновление в `TaskInbox` и локальные HTTP-методы. Без `--db` всё хранится
**только в оперативной памяти**; при `--db` в 5.5 граф записывается в
[приватную SQLite](./TASK_DURABILITY.md) и восстанавливается после рестарта.
Нет аутентификации HTTP-клиента: server-side scope из 5.2 ограничивает
владельца, но любой процесс с доступом к локальному порту действует в
его пределах. Публичный доступ запрещён до полноценной авторизации.

Топологический порядок **не** означает, что задача выполнена, стала
готовой к запуску или была отправлена исполнителю: учёт статусов и
исполнение относятся к последующим пунктам. В 5.3 сервер Netcup не
изменялся, реальный деплой оркестратора не проводился.

**Проверки:** `python3 -m unittest tests.test_task_dag tests.test_task_api -v`
и полный `python3 -m unittest discover -s tests -q`, а также исходники,
компиляция и GitHub `main`. Интеграционные тесты используют реальные
локальные HTTP-сокеты без API моделей, оплаты и внешней сети.
