# WEB-18 — живое подключение на Netcup: BLOCKED (21.11.2026)

**Решение владельца:** WEB-17 удалён из активного чек-листа без перенумерации
других WEB-пунктов; WEB-18 назначен следующим, с проверкой прямо на основном
Netcup, без промежуточного отдельного тестового сервера. Это решение меняет
порядок работ, но не выдаёт OpenAI `POLICY_GO` и не делает mock-порт живым.

  документированный controller `0.3.11a0`). Запрос ничего на Netcup не менял.

  перед status-запросом) содержит WEB-02…16, но `ChatGPTWebConfig.enabled=False`

  `BrowserPort`/`browser_factory`. Все действующие интеграционные тесты

  Автоматическое обновление production на основании такого вывода не
  разрешается без отдельного verified backup, schema-migration/rollback
  и health-теста версии именно на целевом сервере.

## Внешний и технический блокер

- Действующие [Terms of Use OpenAI](https://openai.com/policies/terms-of-use/)
  прямо запрещают *automatically or programmatically extract data or Output*,
  а также обход rate-limits/защит. Предполагаемый серверный unattended
  ChatGPT-web adapter должен программно забирать Output для дальнейших задач.
  Персональная подписка и распоряжение владельца сервером не дают
  исключения из условий сервиса.
- [Официальное описание расчётов](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)
  отделяет ChatGPT subscription от API; subscription не является
  техническим или договорным подтверждением API/bot-доступа.
- Результаты веб-поиска — оценка доступных публичных правил на
  21.11.2026, **не** индивидуальное разрешение OpenAI. Никакой сервисной
  квоты, настоящего браузерного логина, API ключа и `POLICY_GO` нет.

**Результат WEB-18:** `[ ] BLOCKED / NO LIVE SEND`. Проверка работающего
Netcup прошла; подмена real browser mock-портом запрещена к отчётности.
На production не выкладывалось ничего, рабочие базы и сервисы не изменены,
платные API не запускались. Даже загрузка `0.3.41a0` на VPS **не** даст
реального ответа ChatGPT без разрешённого живого канала. Нельзя заявлять
`LIVE_PASS`, `TECH_GO`, `POLICY_GO`, `INTEGRATION_GO`.

**Условие возобновления:** владелец выбирает документально разрешённый канал
для автономной серверной доставки ответов (например, отдельно согласованный
API-путь с известной стоимостью) либо предоставляет разрешение провайдера
на точный автоматизированный режим. Только после этого — безопасная установка
на основной Netcup с записанным live rollback и проверенной схемой БД.
