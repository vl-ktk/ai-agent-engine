# WEB-12 — offline-мост Web mock → существующее ядро задач

**21.11.2026.** Реализация `ai_agent_engine/chatgpt_web_core.py`, тесты `tests/test_chatgpt_web_web12.py`, source `0.3.37a0`. Только Linux/private SQLite и инъектированные mock BrowserPort/WebProject proofs; **нет живого ChatGPT**.

## Что проверяет `WebCoreTaskAdapter`

1. Принимает **неавторитетные bytes** существующей `TaskExecutionRequest v1`. `verify_bound_task_request` пересобирает её из `TaskInbox`, `OwnerScope`, закреплённого worker/workspace и зарегистрированной `WebAgentIdentity` с **точно одной** декларацией `EXTERNAL_REQUEST`. Поле `role.instructions` обязано быть пустым: реальные project instructions и грант берутся свежими из WEB-08, не из JSON задачи.
2. Проверяет зафиксированную владельцем 7.3 `SpecialistPin` в private SQLite: exact owner/project/task/agent, одобренный provider **`chatgpt_web`** и `EXTERNAL_REQUEST` в allowed actions. Нельзя использовать чужую роль/проект, fallback `gpt` или неподтверждённую модель.
3. `SharedCapacity.acquire` требует существующего `ProviderBudget('gpt', ...)` и атомарно резервирует общий GPT CPU/parallel/call budget для **обоих** путей (`gpt` и `chatgpt_web`), не выдумывая новой квоты подписки. В приватном SQLite по-прежнему **schema v17** и provider ledger `gpt`/`claude`; **новую миграцию и live данные не трогали**. Нет слота → задача остаётся `ASSIGNED`, браузер не вызывается.
4. После допуска переводит `ASSIGNED → RUNNING` и вызывает `TaskPermissionGate.run(EXTERNAL_REQUEST)` с durable audit/revocation/emergency-HOLD проверкой **перед** единственным `WebAgentModelRegistry.run`. Далее цепочка WEB-04 project membership → WEB-06 model → WEB-08 fresh instruction/grant и (если настроены) WEB-07/09 проверки выполняются прежним session FIFO до mock BrowserPort. Необязательный типизированный WEB-10 `handoff_receipt` допустим только с exact owner/project/agent/task и затем повторно проверяется WEB-11 по journal/state; без настроенного WEB-11 он не даёт права на отправку. Нет обхода gate через текст модели.
5. Успех требует проверенный один `AgentResult(done, text, 1 step, matching project/agent audit)`; формируется и проверяется существующим `parse_task_response` **строгий v1** с `provider='chatgpt_web'`, конкретным `model_id`, `SUCCEEDED`, только текстом, `artifacts=[]`, `token_usage=null`. Затем durable `SUCCEEDED` и release capacity. В JSON Schema v1 добавлена только допустимая метка канала `chatgpt_web`, без новых типов действий. `timeout_ms=30000` — обязательное поле совместимости контракта, **не** доказанный реальный браузерный таймаут (будущий WEB-14).
6. Любая ошибка после резерва (permission deny, browser exception/неопределённый ответ, SQLite fault) оставляет консервативный `RUNNING`/возможную активную reservation и требует внешнего reconciliation. Нет автоматического повторного браузерного запроса, «вымышленного» успешного ответа или молчаливой подмены модели. Повтор после `SUCCEEDED`/`RUNNING` блокируется в этом процессе, но долговечный delivery-id/lease/ACK и crash recovery относятся к WEB-13/15.

## Проверки и границы

- Позитивный E2E: **реальная приватная тестовая SQLite** → owner-approved specialist pin → `TaskExecutionRequest v1` → capacity + permission audit → mock Web BrowserTurn → `TaskExecutionResponse v1`, задача `SUCCEEDED`, бронь снята.
- Негативные: чужой owner/изменённый request/роль/инструкции/worker/provider, отключённая GPT-ёмкость, общий GPT/Web slot, revoked/missing grant, неразрешённая модель, browser exception, неизвестный итог и параллельная вторая отправка. Без отправки при preflight отказе; при неопределённости slot не освобождается.
- **17 новых WEB-12 unit** (Linux; на Windows пропускаются, так как текущая task SQLite/`flock` официально Linux-only). Итоги полного локального регресса, wheel и GitHub CI дополняются при финальной публикации.

**Не сделано:** реальный Web UI/auth, настоящий `ProjectMemoryStore`→WEB11 adapter (WEB11 всё ещё использует approved injected mock), долговечный at-most-once delivery/ACK, реальный timeout/rate limit, TaskInbox scheduler, полная WEB-16 приёмка, `TECH_GO`/`POLICY_GO`. Никаких дополнительных прав, API расходов или Netcup deployment.
