# 6.12 — фактический приём отчёта и файлов исполнителя системным ядром

## Реализованный внутренний интерфейс

`ai_agent_engine.task_artifacts.TaskArtifactTransfer` принимает **только доверенный результат завершённого** `GPTTaskExecutor` или `ClaudeTaskExecutor`, а также список `ArtifactDescriptor` из контракта 6.5. Вызов выполняется **доверенным управляющим Python-кодом** после завершения задачи:

```python
from ai_agent_engine.task_artifacts import TaskArtifactTransfer

# runner.execute() уже завершился, outcome — его неповторный успешный результат.
transfer = TaskArtifactTransfer(inbox, owner_scope)
bundle = transfer.ingest(runner, outcome, manifest)  # tuple[ArtifactDescriptor, ...]
# Позже, после перезапуска ядра:
restored = TaskArtifactTransfer(reopened_inbox, owner_scope).read_bundle(outcome.task_id)
binary_bytes = restored.read_file("report.bin")
```

`manifest` содержит только относительные пути, ожидаемые размеры, типы и SHA-256. Он **не** предоставляет владельца, проект, worker, workspace, гранты или разрешение на чтение чужих файлов. Текст отчёта берётся только из ранее подтверждённого `GPTTaskOutcome`: `adapt_task_outcome` проверяет provider identity, `executed=True`, успешный терминальный `SUCCEEDED` и ровно одно соответствующее событие provider audit. Дополнительно требуется durable `delivery.completed/success` и неизменное assignment конкретного worker.

**Важно:** этот интерфейс вызывается явно из доверенного кода. Сетевые GPT/Claude CLI по-прежнему выдают только текст, автоматически сканировать рабочую папку или самостоятельно публиковать файлы через этот API они **не** могут. Ядро не читает файловые пути из произвольного текста модели. Прямая раздача файла другому агенту через автоматический scheduler не реализована; теперь ядро может выдать сохранённые bytes только через отдельный scoped Python-чтение.

## Реальные байты, безопасность и лимиты

- Перед копированием ядро на время **переустанавливает эксклюзивный lock той же физической workspace**. Если её уже заняла другая задача, возвращает `workspace_busy`, ничего не читает, не сохраняет и не подменяет чужой результат.
- Используется закреплённый directory FD и `openat` с `O_NOFOLLOW` на **каждом компоненте**. Запрещены абсолютные пути, `../`, symlink, hardlink, FIFO, устройства, владельцы/устройства не из разрешённой workspace. Каталоги защищены `0700`; целевой файл должен быть обычным, с одним hardlink.
- Прочитанное содержимое проверяется по **фактическому размеру и SHA-256** (нижний регистр из 64 hex), дополнительно сравниваются inode/size/mtime/ctime до и после чтения для обнаружения конкурентной модификации.
- Файл: максимум **2 МиБ**; суммарно: **8 МиБ**; максимум **16 файлов**. Эти лимиты намеренно строже синтаксической верхней границы `100_000_000` байт в схеме ответа 6.5. Тип MIME доверяется объявленному полю; он структурно валидируется, но magic bytes/content-type **не детектируются**.
- Текст отчёта и **реальные BLOB-байты** всех файлов сохраняются вместе в **одной транзакции** отдельной приватной task SQLite, схема **v9**. БД и каталоги остаются `0600/0700`. Операция не перезаписывает готовый bundle, не пишет ни в другое рабочее пространство, ни в Git, ни в общую engine DB.
- Scoped `read_bundle(task_id)` читает сохранённую копию даже после освобождения/изменения исходного файла, вновь проверяет соответствие всего манифеста и SHA-256 для каждого сохранённого BLOB. Чужой owner/project не может получить результат через этот интерфейс.

## Отказы и отсутствие ложного успеха

`ArtifactTransferRejected.code` содержит только безопасные категории: `invalid_source`, `invalid_manifest`, `task_not_complete`, `workspace_busy`, `unsafe_path`, `unsafe_file`, `secure_io_unavailable`, `size_limit`, `size_mismatch`, `checksum_mismatch`, `file_changed`, `already_transferred`, `storage_unavailable`, `artifact_corrupt`, `not_found`, `trusted_context_required`. В исключение **не** входят пути файлов, промпты, содержимое, секреты или сырые системные ошибки.

SQLite v8→v9 мигрирует **только свою приватную task-базу**, а также сохраняет возможность контролируемой миграции v1–v7. При сбое БД транзакция откатывает и отчёт, и все byte payloads. Повторный приём того же task не перезаписывает результат. Протокол не делает внешние побочные эффекты модели идемпотентными и не отменяет ограничения недоверенных shell/CLI из 6.8/6.9.
