# 4.20 — восстановление вложенных файлов из локальной копии

## Назначение

Проверить полный цикл `create → verify → restore` для вложенных обычных файлов,
которые отсутствовали в реальном снимке пункта 4.19. Проверка использует
**только синтетические данные** и новый временный каталог; она не обращается
к `/var/lib/ai-agent-engine`, `/var/backups/ai-agent-engine` или секретам Netcup.

## Воспроизводимая проверка

Из актуального checkout репозитория AI Agent Engine под Linux:

```bash
python3 -m unittest discover -s tests -p test_restore_nested_files.py -v
```

Проверка создаёт приватные каталоги и SQLite со схемой версии 2, четыре файла
вложенных путей (текст UTF-8, двоичный и пустой файл) и пустой вложенный каталог.
`LocalBackup` создаёт снимок и проверяет `manifest.json`, SHA-256, SQLite и архив.
В **новом** каталоге исполняются те же безопасные команды восстановления, что и
в пункте 4.19: `cp --no-clobber`, `tar -xzf --no-same-owner`, `tar -dzf`.

Критерии PASS:

- все четыре вложенных файла восстановлены с идентичным SHA-256;
- пустой каталог также восстановлен;
- восстановленная SQLite совпадает по SHA-256 со снимком,
  `PRAGMA integrity_check=ok`, `user_version=2`, тестовая запись сохранена;
- права проверенных каталогов `0700`, файлов и SQLite `0600`;
- исходная SQLite и каждый исходный файл не изменились;
- никакие внешние каталоги и реальные серверные данные не используются.

## Граница доказательства

Это **изолированный интеграционный тест на Linux**, а не восстановление
продуктивных файлов на Netcup, не переключение контроллера на восстановленную БД
и не аварийный переезд VPS. Фактический таймер и самостоятельный off-host backup
проверяются отдельно в следующих пунктах. Временная синтетическая структура
удаляется тестовым раннером после окончания; пользовательские данные не удаляются.
