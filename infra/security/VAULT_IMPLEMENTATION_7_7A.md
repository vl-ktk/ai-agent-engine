# 7.7A — Secure Vault: исходники реализации (0.3.21a0)

**Статус: `[ ] PARTIAL / SOURCE ONLY`.** Этот документ не подтверждает
установку Vault на Netcup или возможность сохранить пароль из текущего
ChatGPT-чата. Для действующей системы ничего не активировано.

## Реализовано в исходниках

- `ai_agent_engine/secure_vault.py`: отдельная private SQLite (каталог `0700`,
  файл `0600`) с application ID, schema version, `foreign_keys`, синхронной
  записью и без незашифрованных значений секретов в таблицах.
- Библиотека `cryptography` объявлена зависимостью пакета. На Netcup она
  **не устанавливалась**; будущий signed-релиз обязан проверить совместимость
  и доступность колеса без изменения старого контроллера.
- AES-256-GCM с независимым случайным nonce для каждой версии и AAD,
  связывающим owner/project/secret ID/версию/тип; ключ передаётся только
  доверенным внешним `key_provider`, не генерируется и не записывается в
  SQLite/исходник. Проверки неверного ключа и подмены ciphertext.
- Динамические категории, стабильные ID, перемещение/переименование,
  обратимое архивирование; идемпотентная область проекта по команде
  доверенного владельца.
- Save/Get/Update/List/Grant/Revoke, отдельный разрешённый Save в категории
  для исполнителя, общие секреты между проектами **без копирования**,
  ограничение по actor/project/operation/expiry и немедленный отзыв grant.
- Метаданные и аудит действий без содержимого секретов. SQL-триггеры
  запрещают штатное `UPDATE`/`DELETE` audit; это **не** внешний неизменяемый
  журнал и не защита при полном захвате владельца SQLite.
- `VaultOrchestratorBridge`: доверенный in-process вызов сохранения секрета
  владельца без второго подтверждения и использование в рамках действующего
  разрешения с возвратом только `bool`, не пароля. Это интерфейс для будущего аутентифицированного чата,
  **не** готовый ChatGPT/MCP/HTTP-коннектор.
- Зашифрованный in-memory snapshot БД и offline-восстановление **только**
  в новую изолированную папку. Экспорт на независимое хранилище и проверка
  фактической off-host доставки ещё не реализованы.

## Нерешённые границы до приёмки

1. Доверенный приём owner-message из живого главного оркестратора и проверка
   подлинной сессии; не разрешать модели передавать себе `is_owner` или grant.
2. Продуманный и проверенный Netcup key provider с автоматической штатной
   разблокировкой при restart и owner-held аварийным recovery material вне VPS.
   Тест перезапуска с тем же **синтетическим** ключом не доказывает этого.
3. Подключение к реальному проектному registry/очереди, проверка прав при
   изменении существующих проектов, без новой самовыдачи разрешений.
4. Подтверждённое off-host резервирование, изолированное восстановление,
   план ротации master key и аварийное удаление после явного owner approval.
5. Security review, CI Linux, live тесты, реальные CPU/RAM/disk и точный
   signed-owner installer/release. Ни одну production-службу не заменять
   до соответствующей проверки версии и безопасного отката.

**Правила для тестов:** только синтетические секреты и временные приватные
папки. Не переносить существующие credential files и не создавать здесь
настоящие пароли, ключи, `.env` или owner recovery secret.
